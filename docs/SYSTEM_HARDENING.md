## Decisions implemented

- Deleted buildings return to inventory. The authored Delete button now says **Store**; its instance name stays unchanged. Creation failure or a missing Backpack preserves the original building and its XP loop. Level, XP, paid status and existing mutation values are carried across.
- Rebirth retains the city, inventory, construction and land, and retains the existing cash reset. Population requirements for rebirths 1?10 are **100, 300, 650, 1,200, 2,000, 3,200, 5,000, 7,500, 11,000, 16,000**. The curve then converges to 142,000 at level 50 and grows 15% per subsequent level. It has no fixed late-game plateau.
- New paid steals save an equivalent-building descriptor before opening the purchase prompt. Confirmed absence permits that replacement. A storage failure, corrupt folder, unloaded owner or active remote session does not count as absence. Existing receipt markers prevent repeat compensation.
- Ambiguous historical price-tier purchases remain pending, as requested. Their product/receipt association is persisted in `PendingReceipts`, prevents another purchase of that product from substituting a new target, and produces recovery feedback. No building is guessed from price. Recovery messages tell players not to purchase again and to provide Roblox purchase history if the issue persists.

## Required integration and remaining limits

1. Sync **server, client and shared together**, including the six new modules listed in MIGRATION.md, then start a fresh Studio Play session. Traffic now depends on its client renderer and shared visual modules. Existing Play sessions do not switch implementations safely through a partial sync.
2. Run `tools/audit_studio.luau` and `tools/audit_commerce_studio.luau` read-only in Studio. Authored templates, hidden legacy asset scripts, sound approval for asset 6525690145 and real developer-product mappings cannot be repaired or verified from this source tree.
3. Play-test owner fresh start and an ordinary returning player; full intro/tutorial, Satchel equip, sell-frame equip, rotations/oversized buildings, Store/re-equip, construction completion/skip, quests/claims, group reward and preserved-city rebirth.
4. Test receipt interruption/retry and two servers. Ambiguous legacy purchases are deliberately unresolved pending recovery, per the user's decision. Active foreign-owner leases defer transfers; no unsafe save or fabricated item occurs on a service error.
5. Measure simultaneous large-city joins and mobile frame/network time. Server transform replication for ambient vehicles is removed, but authored meshes/textures, individual clones, civilian pathfinding, replicated held tools and remaining billboards can still be expensive. No numeric FPS/loading speedup is claimed.
6. Receipt IDs, transfer records and city voters remain permanent deduplication history. Completed receipt payloads are compacted and large profile growth is reported, but a safe sharded/archive history design is still needed before extreme transaction/vote volumes. Deleting that history to achieve an optimization score would break replay protection.
7. Drain old writers before release. Data_1/schema 5 are unchanged; new metadata includes PendingReceipts and CityLikeRewardSequence. CityRatings adds rewardSequence for new likes. A rollback that discards these markers can lose recovery state or repeat rewards. No deployment or live migration was executed here.

The ambient renderer uses Roblox's synchronized server-time estimate for late joins: [Workspace:GetServerTimeNow](https://create.roblox.com/docs/reference/engine/classes/Workspace#GetServerTimeNow). This API contract supports the interpolation design; it is not a benchmark of this place.
